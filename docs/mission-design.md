# 旅行プラン・ミッション設計

担当: 多田 / 目的: ミッションを「技術的に判定できる範囲」で設計し、判定仕様を決める。
議事録(8/22 12:14 MTG)の決定事項ベース: 固定プランベース、判定はカメラ/AR/GPS、Live Activity で進捗表示、心拍×写真で感情の瞬間を特定。

## 1. 基本方針: 判定は「写真 + GPS」に統一

すべてのミッションは **「アプリ内カメラで写真を撮る」ことで達成申請**し、判定は共通パイプライン 1 本で行う:

```
撮影(アプリ内カメラ)
  → その瞬間の GPS を取得
  → [GPS 条件] 目標地点の半径内か(条件がある場合のみ)
  → [AI 判定] 写真がお題を満たすか(Gemini / GPT 画像判定に Yes/No で質問)
  → 達成: Watch 触覚 FB + Live Activity 更新 / 未達: 理由を一言返してリトライ
```

利点:
- 判定実装が 1 本で済む(ミッション追加は JSON を書くだけ)
- どんなお題も生成 AI プロンプトで表現できる(自由度が高い)
- **全ミッションで写真が残る** → 心拍×写真の照合、結果レポート、Journaling 素材にそのまま使える
- 山本さんの API 検証(画像判定系)と直結

心拍・触覚はミッション判定ではなく体験レイヤー:
- 接近時・達成時に Watch 触覚 FB
- 心拍は旅行中ずっとバックグラウンド記録 → 集中スコアと「感情が動いた瞬間」抽出に使用

## 2. 判定モジュール(基本 2 + AR 拡張 3)

「写真+GPS」を基本としつつ、技術アピール用に AR 判定を上乗せモジュールとして持つ。

| 判定タイプ | 技術 | 内容 | 難度 |
|-----------|------|------|------|
| `photo` | カメラ + 生成 AI | 写真がお題を満たすか Yes/No | 低(基本) |
| `location` | CoreLocation | 目標半径内か | 低(基本) |
| `face` | ARKit Face Tracking(TrueDepth) | 表情判定: 笑顔(mouthSmile)、驚き顔、変顔など blendShapes でリアルタイム判定。達成の瞬間を自動撮影 | 中 |
| `body` | ARKit Body Tracking | ポーズ判定: 万歳、指定ポーズの一致(joint 角度)。達成の瞬間を自動撮影 | 中〜高 |
| `vps` | ARCore Geospatial API(チームの Google Cloud キーで有効化済み) | cm 級の位置+向き判定 ※スタンプラリー形式は体験とズレるため除外。採用するなら GO 到着時の AR 演出などに限定(保留) | 高 |

- `face` / `body` は「判定した瞬間にフレームを自動保存」することで、写真が残る設計を維持(心拍照合・レポート素材)
- VPS は Apple の ARGeoTracking が日本非対応のため **ARCore Geospatial API を採用**(Street View カバレッジで東京の屋外は動く。API キーは発行済み)
- AR 判定はデモ映え最優先。実装が間に合わない場合は `photo`(AI 判定)に必ずフォールバックできるお題設計にしておく(例: 笑顔 → 笑顔の自撮りを AI 判定)

## 2.5 ミッションカテゴリ(形式カタログ)

基本 3 種(あなたの案)+ 旅行らしい拡張形式:

| カテゴリ | 内容 | 判定タイプ | 例 |
|----------|------|-----------|----|
| **GO(行く)** | どこかへ行く | location + photo | 東京タワーへ行く |
| **DO(する)** | 何かをする | photo / face / body | 笑顔の写真を撮る、鳥居の前で万歳する |
| **EAT(食べる)** | 何かを食べる | photo | かき氷を食べる |
| **BUY(買う)** | お土産・ご当地品を買う | photo | 500円以内で「いちばん良い」お土産を買う |
| **FIND(探す)** | 現地でお題の被写体を探す | photo | 「いちばん夏っぽいもの」を撮る、赤い提灯を見つける |
| **POSE(キメる)** | 指定ポーズ・表情を現地で | face / body (+location) | 大仏と同じポーズをする、絶景の前で最高の笑顔 |
| **QUIZ(答える)** | 現地でしか分からない謎 | location + テキスト入力 | 「狛犬は何体いる?」に現地で答える |
| **THRILL(ドキドキ)** | 心が動く体験をする | 心拍(Watch) | お化け屋敷・絶叫系・おみくじでドキドキする |

- 除外決定: **STAMP(AR スタンプラリー)** は体験とズレるため除外。**CALM(眺める)** はそもそもスマホをほぼ使わせない前提なので不要
- **THRILL はこのアプリならではの形式**(心拍=コンセプト直結)なので、デモプランに 1 つは入れたい
- QUIZ は判定が簡単(文字列一致)な割に「現地に行かないと解けない」体験が作れるコスパ枠
- 5 ミッション構成の推奨バランス: GO + EAT/BUY + POSE(AR 技術枠) + FIND/QUIZ(自由度枠) + THRILL(コンセプト枠)

## 3. ミッションデータモデル

```json
{
  "planId": "trial-tokyo",
  "title": "はじめての東京旅",
  "missions": [
    {
      "id": "m1",
      "order": 1,
      "category": "go",
      "title": "東京タワーへ行く",
      "judgment": {
        "location": { "latitude": 35.6586, "longitude": 139.7454, "radiusMeters": 150 },
        "aiPrompt": "この写真に東京タワーが写っていますか?"
      },
      "hapticOnNear": true,
      "points": 10
    },
    {
      "id": "m2",
      "order": 2,
      "category": "do",
      "title": "笑顔の写真を撮る",
      "judgment": {
        "location": null,
        "aiPrompt": "この写真に笑顔の人が写っていますか?"
      },
      "camera": "front",
      "points": 10
    },
    {
      "id": "m3",
      "order": 3,
      "category": "eat",
      "title": "かき氷を食べる",
      "judgment": {
        "location": null,
        "aiPrompt": "この写真にかき氷が写っていますか?"
      },
      "points": 10
    }
  ]
}
```

- プランは固定 JSON をアプリ内バンドル(バックエンド不要)
- `judgment.location` が null なら GPS 判定スキップ
- `camera`: front / back(デフォルト back)
- Live Activity には「現在のミッション order / title / 進捗」を表示

## 4. 仮旅行プラン

### 4-1. 実験用プラン(自宅周辺でテスト可能)

1. **[GO]** 近所の公園 or コンビニへ行く(任意の座標に差し替えてテスト)
2. **[DO]** 笑顔の写真を撮る(インカメラ)
3. **[EAT]** 飲み物 or お菓子を撮る

### 4-2. デモ用プラン(発表向け・技術アピール構成)

1. **[GO]** 東京タワーへ行く(GPS + 写真 AI 判定、接近で Watch 振動)
2. **[POSE/face]** タワーをバックに最高の笑顔(Face Tracking がリアルタイム判定 → 自動撮影)
3. **[FIND]** いちばん「夏っぽい」ものを撮る(写真 AI 判定)
4. **[EAT]** かき氷を食べる(写真 AI 判定)
5. **[THRILL]** おみくじを引いてドキドキする(心拍上昇を Watch が検知)

→ 5 つで「GPS / AR 表情 / 生成 AI / 心拍」の技術要素をデモできる構成。

## 5. スコアと勝敗ロジック(案)

- 各ミッション: 達成 pt(+ 判定の早さ/写真の完成度でボーナスも検討)
- **集中スコア**: 旅行中の心拍の変動幅(移動平均からの偏差)が大きい = 感情が動いた = 旅行に集中
- 最終スコア = ミッション pt 合計 × 集中スコア係数
- 勝利条件は体験内容に応じて変える(議事録決定)→ プラン JSON に `scoringProfile` で重み変更
