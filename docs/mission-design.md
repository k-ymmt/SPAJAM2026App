# 旅行プラン・ミッション設計(叩き台)

担当: 多田 / 目的: ミッションを「技術的に判定できる範囲」で設計し、判定仕様を決める。
議事録(8/22 12:14 MTG)の決定事項ベース: 固定プランベース、判定はカメラ/AR/GPS、Live Activity で進捗表示、心拍×写真で感情の瞬間を特定。

## 1. ミッションタイプと判定技術マップ

| # | タイプ | 例 | 判定技術 | 難度 | 実機依存 |
|---|--------|----|----------|------|----------|
| A | 到着する | 「◯◯公園に行く」 | CoreLocation(半径 50–100m のジオフェンス / 距離判定) | 低 | GPS(シミュレータは擬似ロケ可) |
| B | 撮る | 「赤いものを撮る」「空を撮る」 | カメラ + Vision / 生成AI画像判定(Gemini・GPT に「お題を満たすか」を Yes/No で聞く) | 中 | カメラのみ実機 |
| C | 笑う | 「絶景の前で笑う」 | ARKit Face Tracking(blendShapes: mouthSmile)or Vision の表情分類 | 中 | TrueDepth 実機 |
| D | 買う | 「ご当地の何かを買う」 | レシート or 商品をカメラ撮影 → 生成AIで判定(B の応用) | 中 | カメラのみ実機 |
| E | 心が動く | 「ドキドキする体験をする」 | Watch 心拍: 安静時比 +N bpm が M 秒継続で達成 | 中 | Watch 実機必須 |
| F | 静かに味わう | 「5分間スマホを見ずに景色を眺める」 | 画面非注視(端末を伏せる: 近接/姿勢センサ or 画面OFF時間)+ 滞在判定(A) | 低 | ほぼ実機 |

方針:
- **判定の最終手段は「カメラ撮影 → 生成AI Yes/No 判定」に寄せる**(B/D が同一実装で済み、お題の自由度が高い。API キーはチームの Google AI Studio / OpenAI を利用)
- A(GPS)と E(心拍)はネイティブ実装のみで完結する確実枠
- C(笑顔)はデモ映えする AR 枠。時間が無ければ B の「笑顔の自撮りを AI 判定」にフォールバック可能

## 2. ミッションデータモデル(案)

```json
{
  "planId": "trial-shinjuku",
  "title": "はじめての◯◯旅",
  "missions": [
    {
      "id": "m1",
      "order": 1,
      "type": "arrive",            // arrive | photo | smile | purchase | heartbeat | calm
      "title": "◯◯神社に到着する",
      "params": {
        "latitude": 35.0,
        "longitude": 139.0,
        "radiusMeters": 80
      },
      "hapticOnNear": true,         // 接近時に Watch 触覚 FB
      "points": 10
    },
    {
      "id": "m2",
      "order": 2,
      "type": "photo",
      "title": "いちばん「旅っぽい」ものを撮る",
      "params": { "aiPrompt": "この写真は旅行らしい被写体が写っていますか?" },
      "points": 20
    }
  ]
}
```

- プランは固定 JSON をアプリ内バンドル(バックエンド不要)
- `type` ごとに判定モジュール(`MissionJudge` プロトコル実装)を分ける → 分担開発しやすい
- Live Activity には「現在のミッション order / title / 進捗」を表示

## 3. 仮旅行プラン

### 3-1. 実験用プラン(自宅周辺でテスト可能)

開発中の動作確認用。移動を最小化。

1. **[arrive]** 近所のコンビニ or 公園へ行く(ジオフェンス判定)
2. **[photo]** 「緑色のもの」を撮る(AI 判定)
3. **[smile]** 笑顔を作る(Face Tracking)
4. **[purchase]** 飲み物を 1 つ買ってレシートか商品を撮る(AI 判定)
5. **[heartbeat]** その場で 20 回ジャンプして心拍を +20bpm 上げる(Watch 判定)

### 3-2. デモ用プラン(発表向け・観光地想定)

例: 浅草 半日旅(発表時は動画 + 実機デモの組み合わせを想定)

1. **[arrive]** 雷門に到着する(接近で Watch が振動)
2. **[photo]** 仲見世で「いちばん赤いもの」を撮る
3. **[purchase]** 食べ歩きグルメを 1 つ買う
4. **[smile]** 五重塔の前で最高の笑顔を作る
5. **[heartbeat]** おみくじを引いてドキドキする(心拍上昇を検知)

## 4. スコアと勝敗ロジック(案)

- 各ミッション: 達成 pt(+ 判定の精度/早さでボーナス)
- **集中スコア**: 旅行中の心拍の変動幅(例: 移動平均からの偏差の積分)が大きい = 感情が動いた = 旅行に集中
- 最終スコア = ミッション pt 合計 × 集中スコア係数
- 勝利条件は体験内容に応じて変える(議事録決定)→ プラン JSON に `scoringProfile` を持たせて重みを変える
