# 旅行プラン・ミッション設計

担当: 多田 / 目的: ミッションを「技術的に判定できる範囲」で設計し、判定仕様を決める。
議事録(8/22 12:14 MTG)の決定事項ベース: 固定プランベース、判定はカメラ/AR/GPS、Live Activity で進捗表示、心拍×写真で感情の瞬間を特定。

## 1. 基本方針: 判定は「写真 + GPS」に統一

すべてのミッションは **「アプリ内カメラで写真を撮る」ことで達成申請**し、判定は共通パイプライン 1 本で行う:

```
撮影(アプリ内カメラ)
  → その瞬間の GPS を取得
  → [GPS 条件] 目標地点の半径内か(条件がある場合のみ)
  → [AI 判定] 写真がお題を満たすか(Gemini / GPT 画像判定に Yes/No で質問)
  → 達成: Watch 触覚 FB + Live Activity 更新 / 未達: 理由を一言返してリトライ
```

利点:
- 判定実装が 1 本で済む(ミッション追加は JSON を書くだけ)
- どんなお題も生成 AI プロンプトで表現できる(自由度が高い)
- **全ミッションで写真が残る** → 心拍×写真の照合、結果レポート、Journaling 素材にそのまま使える
- 山本さんの API 検証(画像判定系)と直結

心拍・触覚はミッション判定ではなく体験レイヤー:
- 接近時・達成時に Watch 触覚 FB
- 心拍は旅行中ずっとバックグラウンド記録 → 集中スコアと「感情が動いた瞬間」抽出に使用

## 2. ミッションカテゴリ(3 種)

| カテゴリ | 内容 | 判定 | 例 |
|----------|------|------|----|
| **GO(行く)** | どこかへ行く | GPS(必須)+ 写真 AI 判定 | 東京タワーへ行く(タワーが写っているか + 現地半径内か) |
| **DO(する)** | 何かをする | 写真 AI 判定(GPS は任意) | 笑顔の写真を撮る(人が笑顔で写っているか) |
| **EAT(食べる)** | 何かを食べる | 写真 AI 判定(GPS は任意) | かき氷を食べる(かき氷が写っているか) |

- カテゴリは表示・演出用。判定ロジックは全カテゴリ共通(GPS 条件の有無だけ)
- DO/EAT にも GPS を付けられる(例: 「仲見世で」かき氷を食べる)

## 3. ミッションデータモデル

```json
{
  "planId": "trial-tokyo",
  "title": "はじめての東京旅",
  "missions": [
    {
      "id": "m1",
      "order": 1,
      "category": "go",
      "title": "東京タワーへ行く",
      "judgment": {
        "location": { "latitude": 35.6586, "longitude": 139.7454, "radiusMeters": 150 },
        "aiPrompt": "この写真に東京タワーが写っていますか?"
      },
      "hapticOnNear": true,
      "points": 10
    },
    {
      "id": "m2",
      "order": 2,
      "category": "do",
      "title": "笑顔の写真を撮る",
      "judgment": {
        "location": null,
        "aiPrompt": "この写真に笑顔の人が写っていますか?"
      },
      "camera": "front",
      "points": 10
    },
    {
      "id": "m3",
      "order": 3,
      "category": "eat",
      "title": "かき氷を食べる",
      "judgment": {
        "location": null,
        "aiPrompt": "この写真にかき氷が写っていますか?"
      },
      "points": 10
    }
  ]
}
```

- プランは固定 JSON をアプリ内バンドル(バックエンド不要)
- `judgment.location` が null なら GPS 判定スキップ
- `camera`: front / back(デフォルト back)
- Live Activity には「現在のミッション order / title / 進捗」を表示

## 4. 仮旅行プラン

### 4-1. 実験用プラン(自宅周辺でテスト可能)

1. **[GO]** 近所の公園 or コンビニへ行く(任意の座標に差し替えてテスト)
2. **[DO]** 笑顔の写真を撮る(インカメラ)
3. **[EAT]** 飲み物 or お菓子を撮る

### 4-2. デモ用プラン(発表向け)

1. **[GO]** 東京タワーへ行く
2. **[GO]** 増上寺へ行く
3. **[DO]** 東京タワーをバックに笑顔の写真を撮る
4. **[EAT]** かき氷を食べる
5. **[DO]** いちばん「夏っぽい」ものを撮る

## 5. スコアと勝敗ロジック(案)

- 各ミッション: 達成 pt(+ 判定の早さ/写真の完成度でボーナスも検討)
- **集中スコア**: 旅行中の心拍の変動幅(移動平均からの偏差)が大きい = 感情が動いた = 旅行に集中
- 最終スコア = ミッション pt 合計 × 集中スコア係数
- 勝利条件は体験内容に応じて変える(議事録決定)→ プラン JSON に `scoringProfile` で重み変更
